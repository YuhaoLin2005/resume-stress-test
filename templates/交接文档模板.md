# 交接文档模板

交接文档是**三铁律第 2 条**的载体：下一角色只允许从这里了解前序结论。所以它必须**只装结论，不装推理过程**——把推导过程写进去，等于把上一个角色的思维立场一起递了过去。

---

## 【交接文档1】（角色1 → 角色2）

```
候选人身份基准：应届 / 实习 / 社招

风险点清单：
  编号｜类型｜简历原文｜疑点｜追问方向
  R1｜…
  R2｜…

高危问题列表（全文）
  按经历分组，逐题列出

可信度评级：高 / 中 / 低
  （附一句：这是"背调前的可推入面试程度"，不是"是否造假"的判决）

背调核实项：
  1. …
  2. …

用户自测①结果：
  - 答不圆的经历：…
  - 被问死的题：…
  - 用户自己标记「存疑」的经历：…

  【以下为调度器观察，非用户作答】（如有）
  - …
```

> **自测①结果那一栏，用户没汇报就留空并追问一次。不许替用户填。**
>
> **模式A 下用户常常只回一段摘要**（"第 2 题答得不太圆"），不是逐题问答。
> 这种情况**原样记录用户说的话**，观察写在下面单列的那一栏里。
> ⛔ 不要替用户把摘要扩写成 Q&A —— 那是铁律 3 禁止的"替用户回答"。

---

## 【交接文档2】（角色2 → 总结报告）

> ⚠️ **抬头写的是「角色2 → 总结报告」，不是「角色2 → 角色3」。**
> 交接文档2 **不传给角色3**。角色3 的输入只有 JD + 修订版简历两样。
> 写这份文档时不要写成「给角色3 的提示」——一旦写成那样，就等于在给自己开后门。

```
候选人身份基准：…
被检验简历：…（第 N 版）

【角色2 判断摘要】
适配度评级：…
  - 强项：…
  - 弱项：…
卡点：
  ① … ② … ③ …

【JD 穿点排序（角色2 视角）】
  第一穿点：…
  第二穿点：…
  假穿点：…（看起来最可疑、实际最稳的地方）

【单点判别题】
  （一道最能区分「做过」和「没做过」的问题）

【角色2 未解问题】
  U1. …（角色1 未覆盖、留给后续处理）

【角色1 / 角色2 的边界（勿混）】
  - 角色1 问「是不是真的」
  - 角色2 问「做没做透」
  - 同一件事可能两边都出现但**不是重复**：一边问「有没有夸大」，另一边问「推不推得动」，
    结论方向可能相反，**汇总时不要合并**。

⚠️ 修订闸门 —— 两轮自测均未讲圆、但仍留在送往角色3 的简历里的条目：
  （有就逐条列出；没有就写「无」）
  这些条目**不适用**「已通过两轮校验、全部真实」这个前提假设。

用户自测②结果：第二轮仍答不圆的问题及对应经历

简历修订说明：删了什么、留了什么、为什么
```

### 三个名词的定义

| 词 | 意思 |
|---|---|
| **穿点** | 面试官最可能把这份简历戳穿的地方。按可能性排序。 |
| **假穿点** | 看起来最可疑、**实际最稳**的地方。存在的意义是防止准备错方向——你会花力气去补一个其实没问题的点，而真正的穿点在别处。 |
| **单点判别题** | 一道题就能区分"做过"和"没做过"。**只有一道**，不要写成一串。 |

---

## 落盘要求

总控调度器在**第 1.5 步**生成交接文档1，在**第 2.5 步**生成交接文档2。

以下四个文件**都要落盘**：

| 文件 | 内容 |
|---|---|
| `交接文档1.md` | 角色1 的结论，给角色2 用 |
| `自测①-口述自答.md` | 用户本人的回答原文 |
| `交接文档2.md` | 角色2 的结论，给最终总结用（**不给角色3**） |
| `自测②-口述自答.md` | 用户本人的第二轮回答原文 |

**交接文档是过程产物，自测问答是证据。** 后者丢了，这次自检就没留下任何能回头看的东西——而它恰恰是整套流程里唯一"必须由你亲自完成"的部分。
