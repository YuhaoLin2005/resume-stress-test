# resume-stress-test · 简历攻防自检系统

> 投递之前，让 AI 先假装成最不想录用你的人，把你查一遍。

一套**纯提示词**的简历压力测试流程。不装任何东西，把提示词贴进任意 AI 对话窗口就能跑。

## 它做什么

三个视角依次读同一份简历，每个视角只问一件事：

| 层 | 视角 | 只问 |
|---|---|---|
| 角色1 · HR 风控层 | 攻 · 真实性 | 这段经历经得起追问吗？ |
| 角色2 · 业务终审层 | 攻 · 落地能力 | 这个人招进来能干活吗？ |
| 角色3 · 初答回归层 | 守 · 可读性 | 10 秒内 HR 愿意往下看吗？ |

顺序是**故意反的**：先压力测试砍掉水分，再做市场校验确认过筛。这不是在模拟招聘流程，是简历压力测试闭环。

层与层之间夹着两次**自测**——由你本人对着问题口述回答。这两步是整个流程里最便宜、也最容易被跳过的环节，而**最致命的问题恰恰只在这里浮出来**。

## 快速开始

**一句话启动（推荐）**

把下面这段发给任意 AI：

```
访问 https://github.com/YuhaoLin2005/resume-stress-test
读取 prompts/00-总控调度器.md，严格按它的流程执行。
先向我说明模式A/B 让我选，再向我要 JD 和简历。
```

AI 能打开链接就够了。**模式和材料怎么给，它会问你**——不用你先把仓库读一遍。

**如果它打不开链接**（部分网页版没有联网能力）：打开 `prompts/00-总控调度器.md`，全文复制，贴在上面三句话后面，一起发出去。

**本地 CLI Agent（Claude Code / Codex / GLM Coding 等）**

把简历的**文件路径**给它，让它自己读——比手工粘贴省事，而且落盘闸门能真正执行。见 [START.md](START.md)。

**想先试一遍，不想用自己的简历？** [`examples/样例-拿来就能跑.md`](examples/样例-拿来就能跑.md) 里有一份虚构 JD 和虚构简历，直接复制过去就能跑。

## 两种模式

| 模式 | 隔离度 | 什么时候用 |
|---|---|---|
| **模式B · 多窗口** | 最高（真·物理隔离） | **默认推荐**。AI 每阶段给你一个「复制包」，照着念就行，全程不碰提示词原文 |
| **模式A · 单窗口** | 约 90% | 图方便时用。同一对话内依次切换角色，切换前强制输出封存声明 |

单窗口为什么是 90% 而不是 100%：上下文隔离了，但同一个对话流的注意力是连续的。最容易毁掉整次自检的动作，就是让角色3 看见角色1 的怀疑清单——角色3 的任务是「让人愿意往下看」，它一旦知道哪里可疑，就会不自觉地替那份简历辩护。

**最重要的那一份简历，用模式B。**

## 目录

```
resume-stress-test/
├── README.md
├── START.md                    ← 一句话触发的入口
├── prompts/
│   ├── 00-总控调度器.md         ← 核心，三个角色全在里面
│   ├── 01-HR风控层.md           ← 从 00 自动同步生成
│   ├── 02-业务终审层.md         ← 从 00 自动同步生成
│   └── 03-初答回归层.md         ← 从 00 自动同步生成
├── templates/
│   └── 交接文档模板.md
├── examples/
│   ├── 样例-拿来就能跑.md               ← 虚构 JD + 虚构简历，不用自己的也能先试一遍
│   ├── case-01-三层怎么读同一段文字.md   ← 同一段文字，三层读出三种相反判断
│   └── case-02-一次真跑跑出了什么.md     ← 一次真跑的完整复盘，含它跳过的那两步
└── scripts/
    └── sync-modules.py         ← 维护者用，使用者不用管
```

`01/02/03` 是 `00` 里对应段落的**自动同步生成**版，方便多窗口模式单独粘贴。

**改内容只改 `00`**，然后跑 `python scripts/sync-modules.py` 重新生成。

⛔ **不要手动编辑 `01/02/03`。** 模式B 的用户只读这三个文件——改了 `00` 忘了同步，它们会悄悄漂移而**不报任何错**。`scripts/sync-modules.py --check` 就是专门用来让这种漂移亮红灯的。

（使用这个包**不需要**跑任何脚本，直接读 `prompts/` 就行。`scripts/` 只服务于维护。）

## 边界声明（必读）

- AI 只负责**出题**，不判断技术答案的对错。答案真伪要你自己或懂行的人复核。
- 本系统是**自检工具，不是真伪鉴定器**，不能替代真人面试与背景调查，**不构成任何招聘或录用决策依据**。
- 三层给出的评级都是**某个视角下的一次判断**，不是结论。三层之间出现分歧是正常的，而且恰恰是这套方法的价值所在——见 `examples/`。
- 上传前请对姓名、电话、公司内部敏感信息做脱敏。
- **自测环节的落盘文件请留在本地。** 流程会要求你把自测①/② 的口述问答存成文件——那些内容往往是简历上没写的细节。**不要上传网盘、不要截图发群。**

## 三条铁律

整套流程能成立的前提，任何情况下不得违反：

1. **同一时间只激活一个角色。** 激活新角色前，必须先输出「上下文封存声明」。
2. **下一角色只允许依据【交接文档】了解前序结论**，禁止延续上一角色的思维立场。
3. **不得美化简历，不得替用户回答自测问题，不得跳过自测环节。**

第 3 条里最容易破的是中间那句。AI 一旦替你回答了自测题，整个流程就退化成了一次普通润色。

## 已知的边界

- **自测环节依赖你本人。** AI 能出题，不能替你口述。跳过这一步，后面两层查得再细，也只是在检查一份你讲不出来的稿子。
- **单窗口模式不是真隔离**，只是上下文隔离，隔离度约 90%。
- **不同平台输出格式会有差异。** 提示词约束内容，不保证排版一致。
- **AI 会误判。** 它会给出错的判定，也可能漏掉真的问题。把它的输出当线索，不当判决——见 `examples/case-01` 里那次假警报。
